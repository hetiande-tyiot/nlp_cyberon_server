# 需求：110LLM 回覆開頭帶「簡短複述／確認」

> 日期：2026-06-18
> 發件：機器A
> 收件：機器B（sop_api_server / 110LLM）
> 性質：對話體驗優化需求（prompt / SopEngine 行為調整，**不改 API 合約**）
> 相關：機器A 端正在做「承接詞墊話」感知延遲優化（見本文 §5 協調事項）

---

## 1. 為什麼提這個需求

民眾反映「AI 回應慢」。實際延遲鏈約 3–4s，其中 NLP+TTS 約 1s 在你們端、其餘在 MixMonitor buffer 與 VAD。
我們在 A 端會做「承接詞墊話」掩蓋等待，但那只是治標。

另一個**零延遲又能同時提升正確率**的做法，是讓 110LLM 的回覆（`/input` 的 `outputs`）
**開頭帶一句簡短的複述／確認**，再接原本的提問。例如：

| 民眾說 | 現在的 outputs | 希望的 outputs |
|--------|----------------|----------------|
| 有人在打架 | 請問現場大概幾個人？ | **了解，有人在打架。**請問現場大概幾個人？ |
| 板橋文化路 | 請問是路口還是門牌？ | **好的，板橋文化路，我記下了。**請問是路口還是門牌？ |
| 有人受傷流血 | 請問傷勢如何…？ | **我了解，有人受傷流血。**請問傷勢如何…？ |

好處：

- **感知更順**：民眾立刻聽到 AI「聽懂了」，回合更有份量，不像被冷冷追問。
- **正確率**：複述等於即時回讀，民眾若聽到聽錯的內容可當場糾正（尤其地址、人數）。
- **零額外延遲**：複述跟提問在**同一次 `outputs`／同一段 TTS**，不增加任何來回。

---

## 2. 具體需求

請在產生受理員回覆時，於 `outputs` **開頭加入一句簡短複述／確認**，再接既有的提問或指示。

維持現有 API 合約不變：

- `outputs` 仍是字串陣列、依序播放（複述可以併在第一句，或獨立成第一個元素，由你們方便為準）。
- `done`、`error` 語意與時機**完全不變**。
- 不改動端點、不改 `/result` 的 case 欄位。

換句話說，這是 **prompt / 回覆生成風格**的調整，A 端不需要改任何程式即可受惠。

---

## 3. 限制與風險（請務必納入）

複述用錯會比不複述更糟，請在 prompt 加上約束：

| 風險 | 約束 |
|------|------|
| **複述錯誤**（把聽錯的地址/數字唸回去） | **不確定就不要複述**，改用提問確認（「您是說板橋文化路嗎？」） |
| **易聽錯欄位**（地址、電話、姓名、車牌） | 這類資訊寧可用「確認句」而非「肯定句」複述 |
| **回覆變太長** | 複述要**短**（一句、約 ≤10 字）。outputs 變長 → TTS 變長 → 見 §5 半雙工問題 |
| **每句都複述很煩** | 可只在「剛抽到關鍵欄位」時複述，純追問時不必；程度由你們拿捏 |
| **複述與承接詞撞車** | 見 §5 |

---

## 4. 希望可開關／可調（方便 A/B 比較）

如果實作成本不高，希望能用參數控制（環境變數或 `/input` 旗標皆可），預設可先開：

- 開關：是否啟用開頭複述
- 程度：總是複述 / 只在抽到新欄位時複述 / 關閉

這樣我們兩邊能各自實測、比較體感後再定案。若一次到位也沒問題，先做「只在抽到新關鍵欄位時複述」這個折衷最穩。

---

## 5. 與 A 端「承接詞墊話」的協調（重要）

A 端會在民眾停話、等 NLP 的空檔，**立即播一句固定承接詞**掩蓋延遲，候選詞例如：
`嗯`、`好的`、`我了解`、`收到`、`請稍等一下`。

時序是：民眾停話 → A 播「好的」（墊話）→ ~1s 後你們的 `outputs` TTS 接上。

**潛在問題**：如果你們的 `outputs` **也以「好的」開頭**，民眾會聽到
「好的……好的，板橋文化路…」——通用承接詞重複、很怪。

**協調建議（請採用）**：

- 你們的開頭複述**直接帶語意內容**，不要用通用承接詞起頭。
  - ✅「**板橋文化路，我記下了。**請問…」
  - ✅「**了解，有人在打架。**請問…」
  - ⚠️ 避免「**好的。**請問…」「**嗯。**請問…」這種與 A 端承接詞重複的開頭。
- 這樣 A 端承接詞（通用、墊空檔）＋ B 端複述（帶語意、確認）剛好分工、不打架。

A 端承接詞清單最終定案後，我們會再同步給你們一份，避免用詞撞車。

---

## 6. 小結

- 需求：`/input` 的 `outputs` 開頭加一句**短**複述／確認，再接原提問。
- 不改 API 合約（outputs 陣列、done、error、/result 全不變）。
- 零延遲、提升正確率與體感。
- 約束：不確定不複述、易聽錯欄位用確認句、複述要短。
- 協調：開頭**帶語意**、**別用通用承接詞**起頭，以免和 A 端墊話重複。
