# TTS 語速/音量調整：機器 A 端調用方式

> 日期：2026-07-07
> 適用：Cyberon（:8088）與 F5-TTS adapter（:8089）**兩者通用**

## TL;DR

`TtsRequest` proto 本來就有 `speed` 和 `gain` 欄位（Cyberon 官方規格），
你們現有的 pb 檔已包含，**不用重生 pb、不用改連線程式**，
只要在建 request 時多帶兩個參數。

| 欄位 | 意義 | 範圍 | 預設（不帶時） |
|---|---|---|---|
| `speed = 12` (float) | 語速 | 0.5（慢）~ 2.0（快） | 1.0 |
| `gain = 14` (float) | 音量 | 0.5（小聲）~ 4.0（大聲） | 1.0 |

## 程式修改（唯一改動處）

以之前給你們的 grpclib 範例為基準，只改 `TtsRequest` 建構：

```python
req = pb.TtsRequest(
    serviceName="e2e",
    text=text,
    outfmt=outfmt,
    language="zh-TW",
    speaker="Sharon",
    token=TOKEN,
    speed=1.2,   # ← 新增：語速（例：1.2 = 稍快）
    gain=2.0,    # ← 新增：音量（例：2.0 = 兩倍）
)
```

建議把這兩個值做成機器 A 端的 config 項，方便現場調整不用改 code。

## 行為說明

- **不帶欄位 = 維持原行為**（speed=1, gain=1），所以可以先上線再逐步調參
- 兩個引擎（:8088 Cyberon / :8089 F5）都吃同一組欄位，切換 backend 時參數不用動
- F5 adapter 端行為（B 端已實測）：
  - `speed` 是生成時控制節奏（非後製拉伸），0.8 ~ 1.3 區間最自然
  - `gain` 線性增益，超過會削波（clip）保護，不會爆掉，但建議 ≤ 2.0
  - 超出規格範圍的值會被 clamp 回 0.5~2 / 0.5~4
- 實測數據（同一句話）：speed 0.7 → 7.97s、1.0 → 5.57s、1.5 → 3.71s；
  gain 2.0 → RMS 音量正好翻倍

## 建議測試組合

| 情境 | speed | gain |
|---|---|---|
| 預設（先確認不變） | 不帶 | 不帶 |
| 長者/聽不清楚 | 0.8 | 2.0 |
| 一般提示語加快 | 1.2 | 1.0 |
| 邊界值 | 0.5 / 2.0 | 0.5 / 4.0 |

任何問題傳訊給機器 B 端負責人。
