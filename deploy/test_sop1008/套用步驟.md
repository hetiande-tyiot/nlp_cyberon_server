# 912 SOP 調整測試環境：套用步驟

打 911 照舊走正式環境；打 912 走測試環境：程式 `ai/119_1008_SOP`（sop_1008 分支）、GPU1 的模型、port 8300。
案件 json 寫到 `log_119_test/`，資料庫和前端照常寫入，資料庫用 `cases.dialed_number` 分辨。

```
912 → Asterisk 記下撥打的號碼 → amidaemon → apiserver 看到 912 → 8300（測試 119 服務）→ 8093（GPU1 模型）
911 → 同上                                 → apiserver 照舊      → 8100（正式）        → 8091（GPU0）
```

以下指令裡的 `D` 都是本資料夾：

```bash
D=/home/taiyan/project/nlp_cyberon_server_sop1008/deploy/test_sop1008
```

## 套用前

- 挑沒人在測的時間。第 3～5 步會重啟 apiserver、amidaemon，正在進行的通話會斷。
- 第 1 步不影響正式環境，可以先做。

## 1. 啟動測試服務（GPU1 模型 + 8300 的 119 服務）

模型載入 GPU1 大約占 20～30GB 顯存，不影響 GPU0。BERT 會在 CPU 再載入一份，系統記憶體會多用幾 GB。

```bash
sudo cp $D/llama-server-gpu1.service /etc/systemd/system/
# ADDRCHECK 的密碼不放在 git 裡，從正式服務的設定帶進來
TOKEN=$(sudo grep -oP '(?<=ADDRCHECK_API_TOKEN=).*' /etc/systemd/system/sop119.service)
sudo sed "s|__ADDRCHECK_TOKEN__|$TOKEN|" $D/sop119-test.service | sudo tee /etc/systemd/system/sop119-test.service >/dev/null
sudo systemctl daemon-reload
sudo systemctl enable --now llama-server-gpu1 sop119-test
```

檢查：

```bash
nvidia-smi --query-gpu=index,memory.used --format=csv     # GPU1 的用量會上升
curl -s http://127.0.0.1:8300/openapi.json | grep -o '"version":"[^"]*"'   # 應顯示 4.0-119_1008_SOP
```

## 2. 資料表加欄位

要在第 3 步重啟 apiserver 之前做，不然新版 apiserver 寫案件會失敗。

```bash
sudo mysql fire119 < $D/db_alter.sql
sudo mysql fire119 -e "SHOW COLUMNS FROM cases LIKE '%_number'"   # 應看到兩個欄位
```

## 3. apiserver

```bash
cd /home/taiyan/apiserver
git apply $D/apiserver.patch
cat $D/apiserver_config_追加.txt >> config.py      # config.py 不在 git 裡，另外加
sudo systemctl restart apiserver
journalctl -u apiserver -n 30 --no-pager | grep -E 'label|Error|error'
# 應看到「測試環境補進 case 欄位 label：N 條」
```

## 4. amidaemon

```bash
cd /home/taiyan/TYPBX/ai/ami
patch -p1 < $D/typbx.patch
sudo systemctl restart amidaemon
```

## 5. Asterisk（912 撥號規則）

```bash
cd /etc/asterisk
sudo patch -p1 < $D/asterisk.patch
sudo asterisk -rx "dialplan reload"
sudo asterisk -rx "dialplan show 912@internal"   # 應看到 912 的兩行規則
```

## 6. 驗證

各打一通 911 和 912：

```bash
journalctl -u amidaemon -n 50 --no-pager | grep 通話開始      # 會印出「撥打 911／912」
journalctl -u apiserver -n 50 --no-pager | grep 測試環境       # 912 那通會有「🧪 撥打 912 → 測試環境」
ls -t /home/taiyan/project/nlp_cyberon_server/log_119_test | head -3   # 912 的案件 json
sudo mysql fire119 -e "SELECT uuid, dialed_number, caller_number, created_at FROM cases ORDER BY id DESC LIMIT 5"
```

## 還原

照第 5 → 1 步的反方向：

```bash
# Asterisk
sudo cp /etc/asterisk/extensions-internal.conf.bak-20261008 /etc/asterisk/extensions-internal.conf
sudo cp /etc/asterisk/extensions-ai.conf.bak-20261008 /etc/asterisk/extensions-ai.conf
sudo asterisk -rx "dialplan reload"
# amidaemon
cd /home/taiyan/TYPBX/ai/ami && patch -R -p1 < $D/typbx.patch && sudo systemctl restart amidaemon
# apiserver（config.py 要手動刪掉最後加的四行）
cd /home/taiyan/apiserver && git apply -R $D/apiserver.patch && sudo systemctl restart apiserver
# 測試服務
sudo systemctl disable --now sop119-test llama-server-gpu1
```

資料表新增的兩個欄位留著不影響舊程式。要不要刪掉另外討論。
