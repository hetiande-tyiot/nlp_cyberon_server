本文對齊現行程式：主分類模型 **TW-119-BERT_main**、各 **TW-119-BERT-sub_*** 子分類標籤，以及 [`handlers/`](handlers/) 現流程中會主動詢問的 SOP 要素。CaseInfo 中仍存在、但現 handler **不再主動詢問** 的凍結欄位不寫入後續要素表。

## 一、模型與口徑

| 項目 | 說明 |
|---|---|
| 主分類 | `TW-119-BERT_main`（路徑 `/root/autodl-tmp/models/TW-119-BERT_main`） |
| 主類標籤 | 6 類：其他案類、救護、檢舉投訴、火警、災害、緊急救援 |
| 主類測試集 | accuracy ≈ 0.973、macro F1 ≈ 0.872、weighted F1 ≈ 0.974（support 30374） |
| 現行子分類（引擎實際載入） | `TW-119-BERT-sub_救護`（9 類）、`TW-119-BERT-sub_火警_v2`（13 類；權重在 `/root/autodl-tmp/models/TW-119-BERT-sub_火警_v2/`） |
| 已訓練但未接入引擎 | `TW-119-BERT-sub_救護_new`（15 類）、`TW-119-BERT-sub_緊急救援`（5 類）、`TW-119-BERT-sub_其他案類`（2 類） |
| 無子模型 | 檢舉投訴固定映射 `爆竹煙火`；災害資料不足，子類為 `None` |
| 分類依據 | 首輪陳述走主分類；救護子類另可用關鍵詞直判（置信度 1.0），未命中再走 MacBERT，低於 0.7 最多追問兩遍「請問發生了什麼事？」 |
| 流程匹配 | 主類 → `sop_119_engine.py` 的 `_run_救護` / `_run_火警` / `_run_緊急救援`；救護子類 → `handlers/__init__.py` Registry |

**現引擎實際載入**

- 主分類：`TW-119-BERT_main`（[`inference_pipeline.py`](inference_pipeline.py)）。
- 子分類：[`classifier_with_llm.py`](classifier_with_llm.py) `build_classifiers()` 分項載入 **救護**（`TW-119-BERT-sub_救護`）與 **火警**（`TW-119-BERT-sub_火警_v2`）；任一項失敗不拖垮另一項。
- 火警在地址確認後走 [`handlers/火警通用.py`](handlers/火警通用.py)：Q1/Q2（LLM+規則）分流垂片 A/B1/B2/C。每輪拼接報案人文本送火警 BERT，置信度 > 0.5 只填垂片代碼，不改路由、不跳過尚未填滿的垂片問題。
- 緊急救援不載入子模型，一律 [`handlers/緊急救援通用.py`](handlers/緊急救援通用.py)。

**SOP 是否存在**

- **存在（✓）**：該主類有 `_run_*` 分支；且該子類在 Registry 有專屬 handler，或落入通用救護基類（`其它` / 未登記的 `救護`）。
- **不存在（✗）**：引擎僅提示轉專人（其他案類、檢舉投訴、災害）；或子模型標籤現流程不用于分流（緊急救援 5 子類、其他案類 2 子類）。火警 BERT v2 的 13 類用於填碼，SOP 問句由四張垂片共用，見第四節。

**SOP 要素寫入規則**

- 只寫現流程會 `_ask_and_extract`、且對應 [`case_info_119.py`](case_info_119.py) 欄位的問題；問句為 handler 內 canonical 原文。
- 不寫：陳述句 / 安全叮嚀（如「救護車已經派了」「請注意後方來車」）；姓名、聯繫方式等通用收尾；無專屬欄位的閒問（精神異常「現場有沒有家屬陪同？」、墜落傷「你是家屬還是路人協助報案？」）。
- **凍結、不寫入**：`tocc`、`collapse_cause`（仍在 CaseInfo / LLM schema / UI 舊 stage，現 handler 不再詢問）；僅被動抽取、從不主動問的欄位。
- 條件追問需標註（例如急病觸發後才問血糖 / 血壓）。
- 地址確認為救護 / 火警 / 緊急救援共用前置，見第三節，不在每類表重複。

**名稱不對齊**

- 模型標籤 `孕婦待產` vs Registry `孕婦急產`：關鍵詞可進專屬 SOP；`TW-119-BERT-sub_救護_new` 若輸出 `孕婦待產` 無法命中 handler。
- 火警 BERT v2 僅覆蓋 27 案類中的 13 類；其餘靠 LLM 抽取與垂片提問補碼。分流由 Q1/Q2 決定，不直接用 BERT 標籤選 handler。
- `上吊` / `墜落傷` / `孕婦急產` / `燒炭` / `燒燙傷` 不在現行 9 類救護子模型中，但關鍵詞直判仍可進入專屬 handler。

目前統計：**主類 6 類中 3 類已有 SOP、3 類尚無；現行救護 9 子類均有 SOP（含 `其它` 通用流程）。**

## 三、共用前置：地址確認

救護、火警、緊急救援在進入子類 / 通用問診前共用 `_run_address_flow`。已填則跳過；抽取或校驗失敗最多再問一遍，最終失敗標 `address_suspect_error` 後仍繼續後續流程。

| SOP 要素 | 欄位 | 現流程問句 | 備註 |
|---|---|---|---|
| 事發地址 | `address` | 救護：`請先告訴我地址？幾樓？`（無樓層語境時不加「幾樓」）；次問 `請問事發地址在哪裡？幾樓？` | 火警 / 緊急救援首問相同；次問改為建物或路燈編號 |
| 事發地址（火警 / 緊急救援補問） | `address` | `地址在哪裡呢？附近有明顯建物或標示嗎？` | 首問不足時 |
| 路燈 / 電線桿 | `address` | `有路燈或電線桿嗎？給我路燈或電線桿上面的編號、大約靠近哪邊呢？` | 僅火警 / 緊急救援 |
| 行政區 | `address_district` | `請告訴我是那一區？` | 門牌缺區，最多兩遍 |
| 道路 | `address_road` | `請問是什麼路` | 門牌缺路，最多兩遍 |
| 門牌號 | `address_number` | `請問是幾號` | 門牌缺號，最多兩遍 |
| 交叉路口第二條路 | `intersection_road2` | `{第一條路}與哪條路或巷的路口？` | `location_type=intersection` |
| 高速公路 | `highway_name` / `highway_direction` / `highway_kilometer` | `請問在哪一條高速公路、南向或北向，以及幾公里處？` | `location_type=highway` |
| 地址覆誦 | `address_confirmed` | `確定是{地址}這個地址嗎？` | 最多兩遍 |

地標 / 捷運不另追問元件，僅對照 `scripts/landmarks.xlsx`、`scripts/MRTstation.csv`。

救護子類置信度低於 0.7（且非關鍵詞命中）時，最多追問兩遍 `請問發生了什麼事？`（用於再分類，可順便填 `incident_description`）。

## 四、各分類 SOP 要素與現流程問句

以下僅列出 **handlers 現流程會主動詢問** 的 SOP 要素。S1 呼吸僅在意識非 True 時續問；S2 腹部起伏僅在意識與呼吸皆非 True 時詢問。S6 性別 / 年齡依報案人是否即患者、是否多人動態組句。已填欄位自動跳過。

通用收尾（不列入下表）：多數救護子類 `救護車已派出，請問你的姓名與聯繫方式？`；火警改問回撥電話與先生 / 小姐。
