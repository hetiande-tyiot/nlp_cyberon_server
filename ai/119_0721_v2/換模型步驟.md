# 119 智能報案系統 — 換模型 / 換版 操作步驟

> 最後更新：2026-07-23（換版 119_0625_code → 119_0721_v2 完成後整理）

## 架構速覽

- **線上服務**：systemd `sop119.service`，對外 REST API，`http://0.0.0.0:8200`
- **進入點**：`sop_api_server:app`（uvicorn），工作目錄 = `ai/119_0721_v2/`
- **Python 環境**：`/home/cyberon2/nlp_cyberon_server/llmenv/`
- **關鍵原則**：**所有模型路徑都由 service 的環境變數控制，換模型不必改程式碼。**

目前 service 環境變數（`/etc/systemd/system/sop119.service`）：

| 環境變數 | 目前值 | 控制對象 |
|---|---|---|
| `GGUF_MODEL_PATH` | `.../models/TW-119-Model.gguf` | **LLM 抽取/複核模型（gguf）** |
| `BERT_MODELS_BASE` | `.../ai/` | BERT 主/子分類器根目錄 |
| `BERT_DEVICE` | `cpu` | BERT 運算裝置（`cpu` / `cuda`） |
| `LOG_DIR` | `.../log_119` | 案件 JSON log 輸出位置 |

> 程式碼內的 `DEFAULT_MODEL_PATH`（`llm_extractor_119.py`）只是 env 未設定時的 fallback；只要 service 有設 `GGUF_MODEL_PATH`，一律以 env 為準。

## 情境 A：只換 LLM 模型（最常見，例如 Qwen → TW-119-Model.gguf）

1. **放好新模型檔**，例如：
   ```
   /home/cyberon2/nlp_cyberon_server/models/TW-119-Model.gguf
   ```

2. **改 service 的 `GGUF_MODEL_PATH`**：
   ```bash
   sudo sed -i \
     's#^Environment=GGUF_MODEL_PATH=.*#Environment=GGUF_MODEL_PATH=/home/cyberon2/nlp_cyberon_server/models/TW-119-Model.gguf#' \
     /etc/systemd/system/sop119.service
   ```
   （或 `sudo nano /etc/systemd/system/sop119.service` 手動改該行）

3. **重載並重啟**：
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart sop119.service
   ```

4. **驗證**（見下方「驗證」段）。

> ⚠️ 注意：若新模型的 chat template / prompt 格式與 Qwen 不同，`llm_extractor_119.py` 內的 prompt 可能需要對應調整；同底座微調的模型通常相容。換完務必跑一輪真實對話確認抽取結果正常。

---

## 情境 B：換 BERT 分類器模型

BERT 模型放在 `BERT_MODELS_BASE`（= `ai/`）底下，固定目錄名：
```
ai/TW-119-BERT_main            # 主分類
ai/TW-119-BERT-sub_救護
ai/TW-119-BERT-sub_火警
ai/TW-119-BERT-sub_緊急救援
ai/TW-119-BERT-sub_其他案類
```

- **原地更新**：直接用新模型覆蓋對應目錄（保持目錄名不變），然後 `sudo systemctl restart sop119.service`。
- **換到別的根目錄**：改 service 的 `BERT_MODELS_BASE` 指向新根目錄後重啟。
- **改用 GPU**：把 `BERT_DEVICE=cpu` 改成 `cuda`（注意與 LLM 共用 VRAM）。

> 注意：`build_classifiers()` 目前只會註冊「救護」+「火警」兩個子分類器（vendor 行為）。

## 情境 C：換整套程式碼版本（例如 119_0721_v2 → 下一版）

參考本次 0625→0721 換版經驗：

1. 新版目錄放到 `ai/<新版>/`。
2. **確認新版含 REST API 進入點 `sop_api_server.py`**（Streamlit 版的新 code 通常不含，需從本版移植過去並適配引擎介面差異）。
3. 對照檢查相依模組是否齊全：`case_info_119.py`、`case_field_labels_119.py`、`sop_119_engine.py`、`inference_pipeline.py`、`classifier_with_llm.py`、`llm_extractor_119.py`、`handlers/`、`subcategory_keywords_119.py`。
4. 輕量 import 檢查（不載模型）：
   ```bash
   /home/cyberon2/nlp_cyberon_server/llmenv/bin/python -c "
   import sys; sys.path.insert(0,'ai/<新版>')
   import sop_api_server"   # 註：這會載模型，改用逐一 import 各模組驗證符號
   ```
5. 改 service 的 `WorkingDirectory` 指向新版目錄，`daemon-reload` + `restart`。

## 驗證（每次換完都要做）

```bash
# 1) 服務狀態 + 工作目錄
systemctl is-active sop119.service
systemctl show sop119.service -p WorkingDirectory -p Environment --value

# 2) 健康檢查（三個 loaded 應皆為 true）
curl -s http://127.0.0.1:8200/health

# 3) 真實對話煙霧測試（救護 + OHCA 轉人工流程）
B=http://127.0.0.1:8200; PY=/home/cyberon2/nlp_cyberon_server/llmenv/bin/python
SID=$(curl -s -X POST $B/session/new | $PY -c "import sys,json;print(json.load(sys.stdin)['session_id'])")
curl -s -X POST $B/session/$SID/input -H "Content-Type: application/json" -d '{"text":"我阿公昏倒了還有呼吸"}'
curl -s -X POST $B/session/$SID/input -H "Content-Type: application/json" -d '{"text":"新北市板橋區中山路一段161號3樓"}'
curl -s -X POST $B/session/$SID/input -H "Content-Type: application/json" -d '{"text":"對"}'
curl -s -X POST $B/session/$SID/hangup
curl -s $B/session/$SID/result | $PY -m json.tool   # 確認 main_category/address/result 有正確填入

# 即時 log
journalctl -u sop119 -f
```

## 回滾

`restart` 前 service 檔務必先備份：
```bash
sudo cp /etc/systemd/system/sop119.service /etc/systemd/system/sop119.service.bak.$(date +%Y%m%d_%H%M%S)
```
出問題時還原備份 → `daemon-reload` → `restart` 即可。舊版程式碼目錄（如 `ai/119_0625_code`）保留未動，也可作為 code 層級回滾。
