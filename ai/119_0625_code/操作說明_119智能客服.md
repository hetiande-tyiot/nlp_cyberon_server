# 119 智能報案受理系統 — 操作說明

本說明涵蓋 `sop_119_engine.py`（對話引擎）與 `app_119.py`（Streamlit 互動介面）的部署、模型路徑配置與日常操作。

---

## 1. 系統概覽

本系統模擬台灣 119 報案受理流程，目前**完整支援「救護」類別**的 SOP 對話；火警等其他主類別會記錄後提示轉接專人。

### 架構原則

| 元件 | 職責 |
|------|------|
| **SOP 引擎** (`sop_119_engine.py`) | 腳本控制對話流程（問什麼、何時跳過、何時轉人工） |
| **LLM 抽取器** (`llm_extractor_119.py`) | 從報警人回答中抽取地址、生命征象、患者資訊、生成摘要 |
| **主分類器** (`inference_pipeline.py`) | MacBERT 判斷火災 / 救護等主類別 |
| **子分類器** (`classifier_with_llm.py`) | MacBERT 判斷救護子類（急病、車禍等） |
| **Streamlit UI** (`app_119.py`) | 雙欄介面：左側對話、右側欄位面板 |

> **重要**：LLM 只負責「抽取」，**不決定**下一句要問什麼；對話順序由 SOP 引擎腳本固定。

### 線程架構（Streamlit）

```
主線程（UI）  ←→  input_q / output_q  ←→  工作線程（engine.run()）
```

- `input_q`：使用者輸入 → 引擎
- `output_q`：引擎對話 / 欄位更新 → UI

## 4. 模型路徑配置（重點）

所有模型預設根目錄為 **`/root/autodl-tmp/models/`**。若模型放在其他位置，需修改下列檔案。

### 4.1 模型目錄結構

部署時應確保以下目錄/檔案存在：

```
/root/autodl-tmp/models/
├── TW-119-BERT_main/                # 主分類（火警/救護/…）
│   ├── config.json
│   ├── label_map.json
│   └── pytorch_model.bin（或 safetensors）
├── TW-119-BERT-sub_救護/            # 救護子分類
│   ├── config.json
│   ├── label_map.json
│   └── ...
├── TW-119-BERT-sub_火警/            # 火警子分類（可選）
│   └── ...
└── TW-119-Model/
    └── TW-119-Model.gguf       # LLM 抽取 / 摘要 / 分析報告
```

可用以下命令檢查：

```bash
ls -la /root/autodl-tmp/models/TW-119-BERT_main/
ls -la /root/autodl-tmp/models/TW-119-BERT-sub_救護/
ls -la /home/cyberon2/nlp_cyberon_server/models/TW-119-Model.gguf
```

**命名規則**（已由舊版 `macbert_main` / `macbert_sub_*` 更名）：

| 舊目錄名 | 新目錄名 |
|----------|----------|
| `macbert_main` | `TW-119-BERT_main` |
| `macbert_sub_救護` | `TW-119-BERT-sub_救護` |
| `macbert_sub_火警` | `TW-119-BERT-sub_火警` |
| `macbert_sub_緊急救援` | `TW-119-BERT-sub_緊急救援` |
| `macbert_sub_其他案類` | `TW-119-BERT-sub_其他案類` |

> 主分類目錄為 `TW-119-BERT_main`（`_main` 使用底線）；子分類為 `TW-119-BERT-sub_{類別}`（`sub` 前使用連字號）。

程式內目錄拼接邏輯見 `inference_pipeline.py` 的 `_model_dir()` 與 `classifier_with_llm.py` 的 `build_classifiers()`。

### 4.2 修改位置一覽

| 用途 | 檔案 | 變數 / 參數 | 預設值 |
|------|------|-------------|--------|
| **LLM 抽取 / 摘要** | `llm_extractor_119.py` | `DEFAULT_MODEL_PATH`（約第 43 行） | `/home/cyberon2/nlp_cyberon_server/models/TW-119-Model.gguf` |
| **主分類器** | `inference_pipeline.py` | `HierarchicalClassifier(models_base=...)`；子目錄 `TW-119-BERT_main` | `/root/autodl-tmp/models/` |

| **CLI 測試** | `sop_119_engine.py` | `_cli_main()`（約第 840 行） | 同上 |

### 4.3 修改範例

#### 方式 A：改 LLM 預設路徑（全域生效）

編輯 `llm_extractor_119.py`：

```python
DEFAULT_MODEL_PATH = "/你的路徑/你的模型.gguf"
```

#### 方式 B：改分類器根目錄

編輯 `inference_pipeline.py`：

```python
def __init__(self, models_base: str = "/你的路徑/models/", ...):
```

編輯 `classifier_with_llm.py` 的 `build_classifiers`：

```python
def build_classifiers(
    models_base: str = "/你的路徑/models/",
    llm_model_path: Optional[str] = "/你的路徑/模型.gguf",
    ...
):
```

#### 方式 C：僅在 Streamlit 中自訂（推薦，不動底層預設）

編輯 `app_119.py` 的 `_load_models()`：

```python
MODELS_BASE = "/你的路徑/models/"
LLM_PATH    = "/你的路徑/你的模型.gguf"

@st.cache_resource(show_spinner="正在載入模型，請稍候…")
def _load_models():
    ...
    main_clf = HierarchicalClassifier(models_base=MODELS_BASE)
    ...
    sub_clf = build_classifiers(models_base=MODELS_BASE, enable_llm=False)
    ...
    llm = LLMExtractor119(model_path=LLM_PATH, n_gpu_layers=-1)
```

#### 方式 D：LLM 運行參數調整

`LLMExtractor119` 建構參數（`llm_extractor_119.py`）：

| 參數 | 說明 | 預設 |
|------|------|------|
| `model_path` | GGUF 檔案路徑 | 見上 |
| `n_ctx` | 上下文長度 | `4096` |
| `n_gpu_layers` | GPU 卸載層數，`-1` = 全部 | `-1` |
| `temperature` | 生成溫度（抽取建議低溫） | `0.1` |

CPU 環境可設 `n_gpu_layers=0`。

### 4.4 模型載入失敗時的行為

系統採用**靜默降級**策略：

- 主分類器失敗 → 用關鍵詞規則判斷火災/救護
- 子分類器失敗 → 跳過子類標籤
- LLM 失敗 → 用規則備援抽取；摘要改為模板拼接

對話流程仍可跑通，但欄位抽取準確度會下降。

## 5. 啟動方式

### 5.1 Streamlit 互動介面（推薦）

```bash
cd /root/work/119
streamlit run app_119.py
```

瀏覽器開啟後（預設 `http://localhost:8501`）即可操作。

**首次啟動**會載入三類模型，頁面頂部顯示「正在載入模型，請稍候…」，視硬體需等待數十秒至數分鐘。

指定埠號：

```bash
streamlit run app_119.py --server.port 8502
```

遠端存取（若需從外網連線）：

```bash
streamlit run app_119.py --server.address 0.0.0.0 --server.port 8501
```

### 5.2 CLI 終端測試

適合開發除錯，不需瀏覽器：

```bash
cd /root/work/119

# 完整模式（載入所有模型）
python sop_119_engine.py

# 僅測對話流程，不載入模型
python sop_119_engine.py --no-main-clf --no-sub-clf --no-llm

# 載入 LLM 並印出除錯資訊
python sop_119_engine.py --debug

# 組合使用
python sop_119_engine.py --no-sub-clf --debug
```

CLI 參數說明：

| 參數 | 說明 |
|------|------|
| `--no-main-clf` | 不載入主分類器 |
| `--no-sub-clf` | 不載入子分類器 |
| `--no-llm` | 不載入 LLM |
| `--debug` | 在 stderr 印出 LLM 輸入/輸出 |

結束後會在終端印出 JSON 格式的最終案件資訊。

## 6. Streamlit 介面操作指南

### 6.1 版面說明

| 區域 | 內容 |
|------|------|
| **左欄（2/3）** | 對話氣泡、底部輸入框 |
| **右欄（1/3）** | 分類結果、地址、生命征象、患者資訊、案情摘要、AI 分析報告、流程進度 |

### 6.2 基本操作流程

1. 開啟頁面後，系統自動問第一句：**「請問是火災還是救護？」**
2. 在底部輸入框以報警人口吻回答（例如：`救護`）。
3. 依提示逐步回答地址、生命征象、患者資訊等問題。
4. 右欄會**即時更新**已抽取的欄位與案情摘要。
5. 流程結束後顯示「救護車已派出」或「OHCA 轉人工」。
6. 點擊 **「🔄 重新開始新通話」** 可重置整個 session。

### 6.3 右欄功能

- **分類結果**：主類（救護/火警）與子類（急病、車禍等）及置信度
- **事發地址**：含是否已確認
- **生命征象**：意識 / 呼吸 / 腹部起伏（有/無）
- **患者資訊**：性別、年齡、事件描述、目前狀況
- **案情摘要**：每輪自動更新
- **📊 分析報告**：手動點擊生成初報分析報告，可下載 TXT
- **流程進度**：當前 SOP 階段

### 6.4 等待與同步

LLM 抽取與摘要生成需要時間，輸入後輸入框會暫時禁用，並顯示「本輪輸入處理中…」。

- 若右欄欄位未及時更新，可點 **「同步最新狀態」**
- 已安裝 `streamlit-autorefresh` 時會自動輪詢刷新

### 6.5 OHCA 警示

若意識、呼吸或腹部起伏任一項為「無」，系統判定 **OHCA**，會：

- 左欄顯示紅色警示橫幅
- 播放轉人工話術
- 流程以 `ohca_transfer` 結束

## 7. 救護 SOP 對話流程

```
詢問火災/救護
    ↓ 主分類
確認地址（可從首輪回答自動抽取）
    ↓ 复读地址確認（循環直到確認）
子分類（急病、車禍等）
    ↓
生命征象：意識 → 呼吸 → 腹部起伏
    ↓（任一為「無」→ OHCA 轉人工）
患者資訊：性別/年齡 → 事件描述 → 目前狀況
    ↓（已在前文提及的欄位會自動跳過）
案情摘要確認（循環直到確認）
    ↓
結束：「救護車已派出…」
```

### 測試用對話範例（正常派車）

| 輪次 | 系統問題 | 建議回答 |
|------|----------|----------|
| 1 | 火災還是救護？ | `救護` |
| 2 | 地址？樓層？ | `台北市中山北路123號三樓` |
| 3 | 確定是…地址嗎？ | `對，沒錯` |
| 4 | 是否有意識？ | `有意識` |
| 5 | 是否有呼吸？ | `有呼吸` |
| 6 | 肚子有沒有起伏？ | `有` |
| 7 | 性別/年齡？ | `男性，65歲` |
| 8 | 發生什麼事？ | `胸口悶痛` |
| 9 | 目前狀況？ | `意識清楚，還能說話` |
| 10 | 摘要確認 | `對` |

## 8. 程式化整合（開發者）

### 8.1 在 Python 中啟動引擎

```python
import queue, threading
from sop_119_engine import SopEngine119, QueueDialogueIO
from llm_extractor_119 import LLMExtractor119
from inference_pipeline import HierarchicalClassifier
from classifier_with_llm import build_classifiers

input_q  = queue.Queue()
output_q = queue.Queue()
io = QueueDialogueIO(input_q, output_q)

engine = SopEngine119(
    io=io,
    main_classifier=HierarchicalClassifier(models_base="/root/autodl-tmp/models/"),
    sub_classifiers=build_classifiers(enable_llm=False),
    llm_extractor=LLMExtractor119(),
    debug=False,
)

threading.Thread(target=engine.run, daemon=True).start()

# 推送使用者輸入
input_q.put("救護")

# 讀取輸出事件
while True:
    event = output_q.get()
    print(event)
    if event.get("type") == "stopped":
        break
```

### 8.2 output_q 事件格式

| type | 說明 |
|------|------|
| `chat` | `{"role": "assistant"\|"caller", "text": "..."}` |
| `case_update` | `{"case": {...}}` 欄位更新 |
| `classification` | 主/子分類結果 |
| `stage_update` | SOP 階段變更 |
| `stopped` | 流程結束，`result`: `dispatched` / `ohca_transfer` / `error` |
| `error` | 異常訊息 |

## 9. 常見問題排查

### Q1：頁面顯示「主分類器未能載入」

- 檢查 `/root/autodl-tmp/models/TW-119-BERT_main/` 是否存在且含 `label_map.json`
- 確認已安裝 `torch`、`transformers`
- 可暫時忽略，系統會用關鍵詞規則

### Q2：頁面顯示「LLM 未能載入」

- 確認 GGUF 檔案路徑正確（見第 4 節）
- 確認已安裝 `llama-cpp-python`
- GPU 環境檢查 CUDA 是否可用；CPU 可設 `n_gpu_layers=0`

### Q3：輸入後長時間無回應

- LLM 首次推理較慢，等待 10–30 秒
- 點「同步最新狀態」
- 查看終端是否有 OOM 或模型錯誤

### Q4：欄位抽取不準

- 確認 LLM 已成功載入（無黃色警告）
- 用 `python sop_119_engine.py --debug` 查看抽取 JSON
- 檢查 `temperature` 是否過高（建議 ≤ 0.15）

### Q5：修改模型路徑後仍用舊模型

Streamlit 會快取模型實例。修改路徑後需：

```bash
# 重啟 Streamlit，或在瀏覽器選單 Clearing cache → Clear resource cache
```

或刪除 Streamlit 快取後重啟。

### Q6：想擴展火警等其他 SOP

在 `sop_119_engine.py` 的 `_run_main_flow()` 中，目前非「救護」類別僅提示轉接。需新增 `_run_火警()` 等 handler 並在分支中調用。
