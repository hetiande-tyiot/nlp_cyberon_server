# 119 SOP 引擎 — 模型更新紀錄

本檔為跨對話累積的更新總表。**依「改動主題」分區**，每個主題內的條目**依日期由舊到新**排列。
凡門檻／常數皆集中在 `sop_119_engine.py` 頂部，方便實測期調參。

## 使用方式
- 新改動歸到下列對應主題；找不到合適主題再開新主題（維持粗粒度、別太碎）。
- 每條格式：`### [YYYY-MM-DD] 標題（驅動案例 uuid[:8]）` + 「問題／改（檔案:符號）／測試」。
- 同主題內新條目**加在該主題最末**，保持時序。

## 主題 A：主分類與大類路由
（大類判定、其他案類安全網、跨大類轉換）

### [2026-09-09] E1 救護關鍵詞安全網 + E2 其他案類釐清改派（dc0f910e、e4298d36）
- **問題**：BERT 把明確救護案誤送「其他案類」→ 一句就轉人工、不跑 SOP。吞安眠藥自殺（dc0f910e）、鬥毆持械（e4298d36）。
- **E1**：`sop_119_engine.py` `_rescue_override_subcategory` + `_run_main_flow` gate；命中明確救護詞就改判救護。`AMBIGUOUS_RESCUE_SUBCATS`（打架受傷不直轉、交 E2）。
- **E2**：`_clarify_other_category` + `_route_other_from_clarify`；其他案類轉出前追問一次，依答案（不重跑主 BERT、否定感知 `_has_unnegated_token`）改派救護/火警/緊急救援。常數 `OTHER_CLARIFY_INJURY_KW/FIRE_KW/EMERGENCY_KW`。
- **測試**：`tests/test_other_category_routing_119.py`（新增）。

### [2026-09-10] E1 擴及緊急救援→救護（上吊×2 誤送，ff1f6328 / 84be84c7）
- **問題**：「有人上吊」被 BERT 判成緊急救援、細類空白。
- **改**：`_rescue_override_subcategory(text, from_main=)`；gate 從只蓋「其他案類」擴到也蓋「緊急救援」。`SELF_HARM_RESCUE_SUBCATS`（上吊/割腕/燒炭/吞食藥物）。
- **墜落傷規則（用戶告知）**：墜落預設走救護墜落傷；唯受困/夾住/搆不到（`FALL_TRAP_KW`）於分類階段才算緊急救援、不搶回。

### [2026-09-10] 上吊 → 緊急救援 的破門 mid-flow 轉換（用戶規則 + 9/10 上吊案）
- **規則（用戶告知）**：上吊起手走救護上吊流程；流程中發現需消防**破門**（反鎖在家）→ 改判緊急救援、加派消防車。
- **改**：
  - `_escalate_main_to_emergency`：改主類緊急救援、停用救護子類重分類、告知加派消防車；不重跑 SOP、不再問地址。
  - `handlers/base.py` `_maybe_escalate_break_in`：**關鍵字召回 + LLM 確認**（否定感知 `_has_unnegated_token`×`BREAK_IN_KW` 預篩 → 有候選才 LLM 判上下文 → 唯 LLM 明確 false 才擋，安全優先）。
  - `handlers/上吊.py`：S0/S1 被動偵測 + 新增 S3b「進得去嗎/要不要破門」主動問。
- **測試**：`tests/test_other_category_routing_119.py::BreakInEscalationTests`。

### [2026-09-11] 主分類信心/margin 追問（開場含糊、火警↔救護難分）
- **問題**：主分類純取 argmax、不看門檻也不追問；開場一句話含糊（如「有東西燒起來有人受傷」）就直接押大類、走錯整條 SOP。
- **改**：
  - `inference_pipeline.py` `_infer`/`predict`：增回傳主類 `main_probs`（主分類 margin 的資料源）。
  - `sop_119_engine.py` `_do_main_classify`：改回傳 `(main, conf, margin)`；`_run_main_flow` 加追問迴圈——conf<`MAIN_CONF_THRESHOLD` **或** top1−top2<`MAIN_MARGIN_THRESHOLD` 時追問「火災還是救護」（最多 `MAX_MAIN_REASK` 次），再以全文重分類。無分類器的關鍵詞備援回 margin=1.0、純預設回 0.0（觸發追問）。
- **常數**（engine 頂部）：`MAIN_CONF_THRESHOLD=0.7`、`MAIN_MARGIN_THRESHOLD=0.15`、`MAX_MAIN_REASK=1`。

## 主題 B：救護細類分類與探問
（過早定類、含糊病情、意識異常探問、切類）

### [2026-09-09] A 救護分類閘門（4b830f85）
- **問題**：救護細類分類跑在「問發生什麼事」之前，BERT 在空/含糊症狀下過度自信押細類（吞藥意圖未問到就判急病 0.855）。
- **改**：`sop_119_engine.py` `_run_救護` 重問迴圈新增 `no_symptom_yet`；`incident_description` 為空時不論 conf/margin 都先追問一次；首輪用正常語氣初問。
- **測試**：`tests/test_sub_reclassify_119.py`。

### [2026-09-09] C 意識異常主動探問服藥/中毒（4b830f85；90642da6 驗證生效）
- **問題**：急病與吞食藥物表徵（半意識/無反應）重疊，報案人不主動講「藥」就切不出來。
- **改**：`handlers/base.py` `_probe_cause_ingestion`（整通只問一次，flag `engine._cause_ingestion_probed`）。掛點：`handlers/急病.py` 情境 5/10、`handlers/吞食藥物.py` t3（帶 on_answer 觸發 t1/t2 問藥物種類）。
- **測試**：`tests/test_probe_and_count_119.py`。

### [2026-09-10] 急病含糊病情仍問 S0（孕婦待產/吞食藥物/燒燙傷→急病）
- **問題**：開場只說「身體不舒服」被高信心押急病，細類問不出來。
- **改**：`handlers/base.py` `_incident_is_vague`；`handlers/急病.py` S0 改為「未填 **或** 含糊」都再問一次，逼出細類觸發切類。
- **測試**：`tests/test_probe_and_count_119.py`。

### [2026-09-11] 救護細類 margin 閘門 + 多輪偏好晚輪（報案人未描述事件）
- **問題**：救護細類重問只看 top-1 conf<0.7；兩類難分（top1≈top2）仍過關而定錯類；且多輪取 `max(conf)`，讓資訊少的早輪壓過已描述事件的晚輪（全文累積，晚輪資訊必較多）。
- **改**：`sop_119_engine.py`
  - `_do_sub_classify`：改回傳 `(sub, conf, source, margin)`；margin=top1−top2（keyword 命中=1.0，缺 `all_probs` 時 None 防呆，`getattr` 存取）。
  - `_run_救護` 重問條件：conf<`SUB_CONF_THRESHOLD` **或** margin<`SUB_MARGIN_THRESHOLD` 即追問。
  - 候選挑選：改偏好較晚輪——晚輪信心未低於目前最佳超過 `SUB_LATER_PREFER_DELTA` 就採晚輪。
  - 與 2026-09-09「A 救護分類閘門」`no_symptom_yet` 疊加運作。
- **常數**（engine 頂部）：`SUB_CONF_THRESHOLD=0.7`、`SUB_MARGIN_THRESHOLD=0.15`、`SUB_LATER_PREFER_DELTA=0.1`、`MAX_SUB_REASK=2`。
- **測試**：`tests/test_sub_reclassify_119.py`、`tests/test_rescue_vital_flow_119.py`（mock 補回 margin 欄）。

### [2026-09-15] 「要救護車」等純請求不算病情，補閘門（4c012163）
- **問題**：報案人只說「我要救護車」→ 被抽成 `incident_description="需要救護車"`；`no_symptom_yet` 只判**空值**、`_incident_is_vague` 詞表又不含「需要/救護車」，兩道閘門都失效。此時**只要 BERT conf≥0.7、margin≥0.15（明確救護案的正常區間）就會未問病情即定細類**——與信心高低無關（4c012163 該通剛好 0.98，只是佐證數字非門檻）。根因：把「請求」當成「病情描述」。
- **改**：
  - `sop_utils_119.py` 新增共用純函式 `incident_is_vague()` + `_VAGUE_INCIDENT_TOKENS` 補「請求類」詞（需要/救護車/救護/要救/叫救/派救/求救/報案/幫忙叫）。
  - `sop_119_engine.py` `_run_救護` `no_symptom_yet`：改為「空 **或** `incident_is_vague`」都追問。因走 `and not no_symptom_yet`，此條一旦成立則**不論 conf/margin 多高都先追問**。
  - `handlers/base.py` `_incident_is_vague` 改為委派共用函式（原本重複的詞表刪除；急病 S0 同步受益）。
- **界線**：孕婦急產/燒燙傷等雖被 `incident_is_vague` 判含糊（`要生了`/`燙傷` 因 <3 字門檻），但走**關鍵詞直判**（迴圈先 `sub_source=="keyword"` break），不受影響；僅影響走 BERT 的請求類空病情案。
- **測試**：`tests/test_sub_reclassify_119.py::NoSymptomReaskTests`（請求類會追問、具體病情不追問）。
