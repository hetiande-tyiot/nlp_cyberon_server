# 119 地址測試案例

報警人常常「說不清楚」地址：少講縣市、少講區、只講路名、分好幾次補、中途更正。
本檔列出各種說法與期望結果，可直接照著念給系統做人工/實機測試。

自動化版本在 `tests/test_address_cases_119.py`（同一份案例，資料表驅動）：

```bash
cd ai/119_0808_loc_feedback
PYTHONPATH=. ../../llmenv/bin/python tests/test_address_cases_119.py
```

自動化測試一律 mock 掉辖區 API（固定回有效），驗的是**送去查的地址對不對**。
API 本身要另外實測：

```bash
curl -s -G --data-urlencode "addr=新北市土城區中央路2段1號3樓" \
  "http://61.216.64.19:8055/Template/Office/data"
# officeName 非空 = 地址有效；空字串 = 查無管轄單位 → 系統會重問一次再轉人工
```

## 已知缺口（尚未處理，需決定要不要改）

1. **只講到路名、沒門牌時不會追問「幾號」**
   例：「新北市土城區中央路」→ 系統直接覆誦「確定是新北市土城區中央路這個地址嗎？」。
   實機上辖區 API 會回空 → 重問一次完整地址 → 仍不行就轉人工。
   若要改善，需在 address 分支加一段「缺門牌就補問」的追問（會動到 SOP 話術）。

2. **純延續片段的規則備援抽不到**
   `extract_address_hint("2段1號3樓")` / `("1號3樓")` 回 None。
   正式環境有 LLM 抽取所以走得通；LLM 掛掉時這類回答會漏。
   放寬有風險（「3樓」也會被當地址），暫不處理。

3. **路口類地址不補縣市**
   F60 結果是「板橋區仁化街與文化路路口」，沒有「新北市」。
   路口不送辖區 API，只影響顯示與派遣單。

4. **`ensure_city_prefix` 對他縣市地標無防護**
   「士林夜市」若被判成 address 類別會補成「新北市士林夜市」。
   實際上這類說法會被判成 landmark，不走這條路徑，但值得注意。
